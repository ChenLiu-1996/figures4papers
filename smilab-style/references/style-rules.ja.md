# smilab-style 図のルール（ドラフト v0・日本語レビュー用）

参照図：`references/images/01_…` 〜 `33_…`（全 33 枚）。本文中の `#05` のような番号はファイル番号。

---

## 0. 全体の結論：なぜ綺麗に見えるのか

1. **色数が少なく、意味を持っている**：1 枚あたり 3〜5 色相まで。各色は「1 概念＝1 色」で図全体（さらに論文内の全図）で一貫している。
2. **薄い塗り＋同じ色相の濃い枠線**（tonal pair）：塗りは淡いパステル、枠線は同じ色相を濃くしたもの。色が多くてもうるさくならない。
3. **主役と脇役の差がはっきりしている**：提案手法・新規モジュールだけに色や太字・太枠を使い、既存部品（Projection, Tokenizer, LayerNorm 等）や比較手法はグレー／淡色で引かせる。
4. **論文の記法と図の記法が一致**：$\boldsymbol{X}$, $\boldsymbol{h}_t$, $\hat{y}$, $\mathcal{L}_\mathrm{ATT}$ などを本文と同じ LaTeX 記法で図中に書く。
5. **抽象的な処理に具体的な実データを添える**：スペクトログラム、脳表、動画フレーム、波形などの実物サムネイルを入れて「何が入って何が出るか」を一目で分からせる。
6. **グリッドに揃っている**：同種ブロックは同じサイズ・同じ間隔、矢印は直角配線、テキストのベースラインが揃っている。
7. **模式図とプロットで視覚語彙を共有**：模式図で使ったバッジ・色・アイコンを結果プロットでも再利用（#28–30 の数字バッジ、#12–17 の手法色）。

## 1. 色

### 1.1 パレットの作り方
- **淡い塗り（明度高・彩度低）＋同色相の濃い枠**を基本単位にする。例：
  - 青系 塗り `#E8EEFA` / 枠 `#7A96D6`（#01 条件ボックス、#26 、#21）
  - 黄系 塗り `#FFF6DA` / 枠 `#E9C866`（#02 S5 Layer、#21 Codec-aware）
  - 紫系 塗り `#EDE3F3` / 枠 `#A77DB8`（#04 Flow-SSM Block、#06 AHBS）
  - 橙系 塗り `#F9E3CC` / 枠 `#E8A36A`（#04 (b) S5 Layer、#06 DINOv2/SigLIP、#07）
  - 緑系 塗り `#E3F1E1` / 枠 `#7FB77A`（#01 音声提示、#21 Token Mixer、#26 Intent-Palette）
  - 赤ピンク系 塗り `#FBE4E1` / 枠 `#E08A82`（#01 Decoding Model、#29 LVLM、#23 Scoring head）
  - ニュートラル 塗り `#F2F2F2` / 枠 `#9A9A9A`（汎用部品）
- 背景パネルはさらに淡い同系色（アルファ 0.15〜0.3 相当）で、中の部品を邪魔しない（#02 Forward/Backward Scan の紫／赤パネル、#26 の緑／橙モジュール）。
- グラデーションは「2 つの状態の混合」を意味するときだけ使う（#06 橙→紫トークン、#18 Flow as Flow の赤→青文字、#04 の Flow Matching 軌跡）。

### 1.2 色の意味づけ（セマンティクス）
- **1 概念＝1 色を図内・論文内で固定**する。
  - #07：橙＝Dense、緑＝Moderate、紫＝Coarse sampling。枠色・凡例・本文すべて共通。
  - #08–09：青＝"Wind blows"、黄＝"man speaks"、紫＝"goat bleating"。テキストのハイライト・スペクトログラムの枠・エンコーダの塗りがすべて同色。
  - #14–17：LCMV＝茶、sLORETA＝緑、wMNE＝青、…、**CANDLE＝赤ピンク**。4 枚の図で完全に共通。
- **提案手法は暖色（赤・ピンク・橙）**で強調、比較手法は寒色／茶／グレーで後退させることが多い（#14–17, #33 は逆に Ours＝緑だが「良い＝緑」の意味づけと一致）。
- **✗＝赤、✓＝緑** の評価記号を統一（#08, #20, #22, #32）。
- **❄＝凍結（frozen）、🔥＝学習可能（trainable）** のアイコンを部品の左上またはラベル前に置く（#01, #06, #20, #23, #26, #31）。

### 1.3 データプロットの配色
- 棒グラフ：パステル（alpha 0.6〜0.75 程度）塗り＋**同色の少し濃い枠 or 枠なし**（#14–16）。原色ベタ塗りは使わない。
- 折れ線：やや彩度高めの太線（2.5〜3 pt）＋マーカー（#10）。
- 例外的にベタの飽和色（#30 の青 `#2B2FE0` 系）を使う場合は、背景を薄グレー `#F5F5F5` にしてコントラストを和らげる。
- ヒートマップは発散カラーマップ（青—白—赤, `coolwarm` 系）（#24）、強度マップは `YlOrRd` 系（#12, #14–16 の脳表）。

## 2. 文字（タイポグラフィ）

- **フォントは 1 枚の中で 1 系統**：
  - セリフ系（Times / Computer Modern 系）：本文 LaTeX と馴染む。#01–05, #12–17, #24, #30 など。
  - サンセリフ系（Helvetica / Arial 系）：模式図・ティーザー向き。#06–11, #18–19, #26, #32–33 など。
  - → smilab-style では **論文本文に合わせて Times 系を既定、ティーザー／スライド用はサンセリフ** を提案（要確認）。
- **数式は必ず LaTeX 記法**：ベクトル・行列は太字斜体（$\boldsymbol{X}, \boldsymbol{h}_t$）、集合は筆記体（$\mathcal{G}, \mathcal{I}$）、添字は立体（$\boldsymbol{x}_\mathrm{cand}$, $\boldsymbol{X}_\mathrm{vis}$）。
- **階層は 3 段まで**：
  1. パネル見出し：太字（例 "Experimental condition", "(a) Flow-SSM Block"）。見出しはパネル枠と同じ色にすることがある（#04 紫見出し／橙見出し／紺見出し）。
  2. 部品ラベル：通常ウェイト。
  3. 補足（"×24 trials", "(See Sec. 4)", "×L Blocks"）：小さめ or 括弧書き。
- **パネルラベル**：`(a)`, `(b)` 太字を左上に置く（#03, #11, #14–16）、または図下中央にキャプション風に置く（#07, #21, #28–29）。1 本の論文内でどちらかに統一。
- **テキスト入力（プロンプト・クエリ）は斜体＋ダブルクオート＋点線枠**（#06, #08, #09, #26）。
- 縦長ブロック内のラベルは**90° 回転**（LayerNorm, FFN, DiT block, Scoring head など：#02, #04, #19, #23）。
- 図中の文字サイズは**印刷時に本文キャプションと同程度（8–10 pt）**。最小でも 6 pt。

## 3. 模式図（アーキテクチャ／パイプライン）の作法

### 3.1 形とその意味
| 形 | 意味 | 例 |
|---|---|---|
| 角丸長方形（小さめ半径） | 処理ブロック・モジュール | ほぼ全図 |
| **台形** | エンコーダ／ヘッド（次元を縮める・広げる） | #08, #09, #12, #22–23, #29 |
| 縦長の細い長方形（回転ラベル） | 層（LayerNorm, FFN, DiT block） | #02, #04, #19 |
| 点線の長方形 | 入力テキスト、状態変数、凡例、グループ化（×L ブロック） | #02, #06, #09, #21, #31 |
| 円の中に演算子 ⊕ ⊗ ⊙ ⊖ | 加算・積・要素積 | #02, #04, #12, #13, #31 |
| **少しずつずらして重ねたカード** | 複数枚・時系列・バッチ（T 枚、スライス、フレーム） | #12, #13, #16, #21, #26 |
| 正方形タイルの列 | トークン列 | #06, #20, #21, #26 |
| 円柱 | データベース | #25 |

### 3.2 線と矢印
- **矢印色は中間グレー（`#555`〜`#777`）**、細め（0.8–1.2 pt）、小さい塗りつぶし矢じり。真っ黒は強調時のみ。
- **直角配線（マンハッタン配線）** を基本とし、斜め線は「概念的な対応」を示すとき（#08 色付き矢印、#12 点線曲線）に限る。
- 線が交差するときは**ジャンパー（飛び越し）**を描く（#02, #04）— 接続と交差の区別が付く。
- **実線＝データフロー、点線＝反復・フィードバック・推論時のみの経路・概念対応**（#04 の $\hat{x}_t$ ループ、#12 の射影、#28 の再推定）。
- 色付き矢印は「その色の概念の流れ」を示すときのみ（#07, #08, #31 forward 黒 / backward 赤）。
- 分岐・合流は**同じ x / y 座標で揃えて**束ねる（#04 の β, γ, α 線、#26 の $l_+$ から 5 本）。

### 3.3 レイアウト
- **左→右（または下→上）の 1 方向フロー**。読み順が迷わない。
- 大きな図は**2〜3 パネルに分割**し、パネル間を
  - 縦の点線（#07, #08, #24, #32）または細い実線（#03, #17, #21）で区切る、
  - またはパネル自体を淡色背景の角丸枠で囲み、左上に太字見出し（#13, #18, #19, #26）。
- 細部の拡大は**色付き枠＋曲線矢印で吹き出し**（#04 S5 → (b) S5 Layer の橙矢印、#15 赤枠ズーム）。
- 同種ブロックは**同幅・同高・等間隔**。
- 凡例は**図の右上 or 右下の空きに、細いグレー枠（点線 or 実線）で囲んで**配置（#07, #09, #13）。

### 3.4 ティーザー（Figure 1）の型
- **「既存手法 ✗ vs 提案手法 ✓」の左右（上下）対比**（#08, #20, #22, #28, #32）。
- 下段 or 右側に**数値の比較ボックス**を並べ、提案手法だけ**太字・太枠**、人間評価を ≈ で並べる（#08, #22）。
- 吹き出し的に**絵文字・アイコン（👤, 🎬, 😊/☹）**を控えめに使って直感的にする（#22, #25, #33）。
- 実例（実際の入力画像・キャプション）を必ず入れる。

## 4. データプロットの作法

### 4.1 共通
- seaborn `whitegrid` 相当：**薄グレーのグリッド（`#E5E5E5` 程度）、上・右スパインなし or 薄グレー枠**。
- **軸ラベルに単位 [mm], [s], [%] と「良い方向」矢印 ↓ / ↑** を付ける（#14–17）。
- 提案手法は**最後（右端／最下）に置き、凡例では太字**（#14–17 の **CANDLE**）。
- 複数サブプロットで同じ量を描くときは**凡例を 1 つにまとめて上部 1 行**に置く（#10）、または右に縦 1 列（#14, #15）。
- 凡例マーカーは**角ばった四角パッチ**（#11, #14–16）。
- 有意差は**棒の上に `*`, `**`, `***`**（#14–17）。

### 4.2 棒グラフ（#14–16, #30）
- **値を棒の中（下端寄り）に縦書き**で入れる → 上部に星印のスペースを確保しつつ数値も読める。
- エラーバーは黒、細線、小さいキャップ。
- y 軸は 0 から始めないことがある（差を見せるため）→ 誤解を招かない範囲で、軸の起点を明示。
- #30：**目盛ラベルを角丸グレーのバッジ**、注目値だけ赤バッジ → 模式図 (#28–29) と同じ部品を再利用。

### 4.3 横棒アブレーション（#17）
- 完全版（Full model）だけ**色付き（提案色）**、他はグレー `#DCDDE0`。
- グループ見出し（Architecture / Loss / Simulator ablation）を**太字で左寄せ**、各行は `(b-i) w/o fθ` のように番号付き。
- 各列ごとに**最良値を太字**。
- タスク群を**縦の実線**で区切り、列見出しに引用元 `(Parmigiani et al.)`。

### 4.4 折れ線（#10）
- 手法ごとに**色＋マーカー形状**の両方を変える（白黒印刷でも区別可能）：◆ ▲ ■ ●。
- 線は太め（≈2.5 pt）、マーカーは大きめ（≈8–10 pt）。
- サブプロットタイトルは枠の上中央、y ラベルは左端のみ。

### 4.5 散布図・バブル（#05, #33）
- **凡例の代わりに点の横に直接ラベル**（手法名＋パラメータ数）を同色で書く（#05）。
- マーカー形状＝手法、線種（実線/破線の縁）＝データセット、のように**視覚変数を役割分担**。
- 半透明（alpha≈0.6）＋濃い縁で重なりを見せる。
- #33：**バブル大きさ＝コスト**、提案手法への**太い緑矢印**、比較手法群を**赤の点線枠**でまとめ、評価軸ごとに 😊/😐/☹ で要約 — メッセージを図だけで伝える。

### 4.6 その他
- ヒストグラム＋Sankey（#11）：ビン（0.0–0.2 …）の色を両パネルで共通にし、平均値を点線＋数値ボックス（枠色＝系列色）で示す。
- ヒートマップ行列（#24, #26）：対角や注目セルを**太い色枠**で囲む。セル内数値は小さめ。

## 5. 一貫性ルール（論文単位）

1. 手法 → 色 の対応表を論文で 1 つ作り、全図で使う（#14–17）。
2. 新規モジュール → 色 の対応を模式図と結果図で共有。
3. フォント・パネルラベル位置・矢印色・角丸半径を論文内で統一。
4. ❄/🔥、✓/✗ などのアイコンは論文内で同じ意味のみに使う。

---

## 6. やらないこと（参照図から読み取れる NG / 注意点）

- 原色ベタ塗りの大きな面、3D 効果、強いドロップシャドウ（参照図の影はごく薄い）。
- 1 枚に 6 色相以上を「意味なく」使う。
- 本文と異なる記号（図では $h$、本文では $\boldsymbol{h}$ など）。
- **スペルミス**：参照図にも "Hierachical"(#07), "Attentnion"(#26), "Sculp"(#12), "descriptivenss"(#31) がある → 書き出し前にスペルチェック必須。
- 矢印の黒・グレー混在（意味がないなら統一）。

## 7. 確認したい点（レビュー時に教えてください）

> v1 実装では暫定的に次を採用：1 = Times（ティーザーのみ Helvetica）、2 = `#D9837F`、3 = 左上太字 `(a)`、4 = 両方含む（`schematics.md`）、5 = 目測値のまま。

1. 既定フォント：Times 系（本文合わせ）でよいか？ティーザーのみサンセリフ可とするか？
2. 提案手法の既定色：赤ピンク系（CANDLE 風 `#D98880` 付近）でよいか？
3. パネルラベル：`(a)` 左上太字 と 図下キャプション風 のどちらを既定にするか？
4. 本 skill の対象：matplotlib プロットのみか、模式図（draw.io / PowerPoint / Figma で作るもの）のガイドラインも含めるか？
5. 上の色コードは画像からの目測。実際に研究室で使っているカラーコードがあれば差し替えたい。
